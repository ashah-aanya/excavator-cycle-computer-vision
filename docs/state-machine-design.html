The State Machine

Two passes, four swappable cues, one loop · not yet built — this is the design

Why two passes

  • • A cue that fails on the whole video can work inside a window. The prior session's d²h/dt² cue landed 6.14 s early searching a 14-second bracket — it found a louder event elsewhere.
  • • Pass 1 is deliberately generous: missing the truth is fatal, a loose window just costs pass 2 more searching.
  • • Pass 2 is precise and local: it only finds the best instant in a region it was told contains one.

Forward and backward

  • • The search is not forward-only. An onset is where a signal left rest, which you find by spotting the excursion and walking back to its start.
  • • So window_for extends a configurable lookback before the current phase began, and frame_for searches whichever direction the cue needs.
  • • onsets.motion_boundary(mode="arrives"|"departs") already does this walk and is tested — it just has no caller yet.

Three properties that are free

  • • Ordering — window_for is lower-bounded by state.since, so dumping cannot be found before hauling. Not a check; an impossibility.
  • • Multi-cycle — the loop simply keeps going. Nothing is written per-cycle.
  • • Head and tail partials — a cycle is dig-onset to dig-onset, so footage outside that is in no cycle.
  • • Not free: a mid-video re-dig. The machine sits in hauling looking for dumping, never finds it, and abandons with a reason.
