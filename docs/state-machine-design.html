Calibrate globally, search locally · always watching for digging · BUILT — this page is the original design; see the note below for where the code diverged

What changed from the first design

  • • The old version cut the video into dig episodes with a global Otsu and walked those. That made digging a different mechanism from the other three — found globally and non-causally while everything else was found locally and in sequence.
  • • Now Otsu only sets levels. What "low" means comes from the whole video; when it happened comes from the walk. All four transitions are found the same way.
  • • It also degrades better: a single global split assumes the whole clip is bimodal. A sliding window doesn't care what happened 40 seconds ago.

Always watching for digging

  • • Digging is the cycle boundary, so it is the only transition that re-establishes where we are. Watch it only in sequence and one missed onset loses every later cycle.
  • • But at a higher bar than the in-sequence check: expected evidence is cheap, unexpected evidence should be expensive. A spurious dig mid-haul would silently truncate a good cycle.
  • • Paired with a derived timeout — k × the median gap between digging onsets seen so far. A constant would be tuned to one video. No timeout on cycle 1, since there is no history yet.

Two counters, on purpose

  • • cycle_count counts what the machine did. The averages come from what we could measure. A cycle is complete whether or not we pinned all four of its onsets.
  • • Telling "we missed a cue" from "no cycle happened" needs a weaker second check: did the phase leave any evidence at all? Truck overlap rose somewhere → dumping happened, the cue failed.
  • • Consequence worth knowing: cycle_count and the averages come from different populations, so their product will not equal the elapsed time. That is correct, and it will look like a bug later.

HISTORICAL DESIGN · fsm.py and cycles.py now exist and diverge from this page in several places: there is no derived timeout (a mid-cycle re-dig abandons and restarts instead), MachineState carries no cycle lists and no validate(), windows reach BACKWARD from the trigger rather than forward, pass 2 refines each window as it is found rather than waiting for all four, and refine() estimates the rest band rather than calling motion_boundary(). cycle_count counts cycles that OCCURRED, not len(cycles). Read src/excavator_cycles/fsm.py for what is actually built.
