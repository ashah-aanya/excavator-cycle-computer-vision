Excavator Cycle Pipeline

19 modules, 5,367 lines · bounding-box kinematics, no optical flow, no arm chain · branch minimal-bbox-pipeline

Where to start reading

  • • boxes.py (261) — smallest real module. Masks to boxes, then a moving average whose window is a duration, not a sample count.
  • • features.py (384) — the physics. Read the module docstring first: it states the two sign conventions and why there is no dy_dt.
  • • cabin.py (422) — the cabin reference, plus the diagnostic that measured how still it is.
  • • track.py (1009) — the biggest, and the one you can skip. It is perception, it works, and nothing in this rebuild changed it.

The rule everything obeys

  • • Nothing video-specific. Frame rate, truck box, slew centre and L are all derived per video.
  • • Lengths divided by L (arm reach in px) — a feature means the same on a 480-wide clip and a 1920-wide one.
  • • Rates per second, from the decoder's real timestamps, never a frame index.
  • • Brackets from Otsu splits of the video's own distributions — no tuned signal thresholds anywhere.
  • • Verified: derived truck box (235,134,377,211) vs the hardcoded (234.5,134.0,376.5,211.0).

What is missing, deliberately

  • • fsm.py and cycles.py — stages 3 and 4. The agreed pause point.
  • • So there is no answer.json yet: the pipeline produces the evidence, not the conclusion.
  • • The pass-2 primitives exist: motion_boundary() is tested; otsu_threshold() reached this diagram with no caller and no test, and a tie-breaking bug that pinned its threshold to the bottom of the gap. fsm.calibrate() now calls it, and it now has tests.
  • • Two known gaps for stage 3: only the first cycle is measured, and a mid-video re-dig would count as a complete one.
