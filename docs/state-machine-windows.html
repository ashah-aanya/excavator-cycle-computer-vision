Phase State Machine — Two Passes

Each state = one phase. Pass 1 finds the window its start falls in; pass 2 picks the frame. (weight) = vote strength.

Why two passes

  • • A single cue that fires on one frame is brittle: noise makes it early or late
  • • Pass 1 trades precision for reliability: independent cues must agree on a window
  • • Pass 2 trades reliability for precision, but can only answer inside that window
  • • A wrong frame costs a fraction of a second; a wrong window can cost a whole cycle

Why gates come first

  • • Shapes repeat: "flat → starts rising" happens at both the haul and the dump
  • • Gates encode physics ("can't dump unless over the truck side of the cabin")
  • • They stop large errors and cascades; they barely sharpen timing
  • • "Above the dig height" is relative to THIS cycle, never a fixed number

Known weak points

  • • Strict order: a repeated or skipped phase is misattributed or stops the search
  • • Vote weights (3/2/1) and window widths are judgment calls, not derived
  • • Everything downstream depends on the bucket mask staying on the bucket
  • • Lives in eval/ today (interval_votes.py, find_onsets.py); run.py still uses fsm.py
